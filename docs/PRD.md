## 1. 需求分析

### 1.A 交付目标

交付一款 **Android 平台、纯本地目录** 的漫画阅读器 App，名称 **ComicNest**，界面中文，最终产出一个 **可正常安装的正式签名 APK**（非测试/调试版，避免部分手机以"仅测试版"为由拒绝安装）。

核心能力目标：

| 编号 | 能力 | 说明 |
|------|------|------|
| G1 | 本地目录导入 | 通过系统文件选择器（SAF）授权一个或多个"库根目录"（目录A、目录F…），**只读取不复制** |
| G2 | 漫画库扫描 | 识别 `库根目录/漫画名/图片…` 结构，将每个"漫画名"作为一部漫画 |
| G3 | 主页总览 | 展示"漫画名 + 首图预览"，网格布局；支持按**名称**排序（默认）与按**导入时间**排序；可翻页/滚动浏览 |
| G4 | 阅读器 | 图片按**文件名自然序**排列（保证 `001.png` 在 `002.png` 之前）；**默认下拉式（Webtoon）**，可切换**左右翻页（Pager）** |
| G5 | 图片格式 | 至少支持 jpg、jpeg、webp、png、gif、bmp 六种；尽量兼容 avif/heif 等常见格式 |
| G6 | 随机阅读 | 主页一键随机选取一部漫画并开始阅读 |
| G7 | 收藏夹 | 可创建/命名多个收藏夹，将漫画加入收藏夹；**指向式引用（不复制文件）** |
| G8 | 工程质量 | UI 美观（现代框架）、架构可扩展（为"未来可能的联网检索"预留抽象）、健壮性（边界/异常/极端值）、响应速度优化 |
| G9 | 交付物 | 正式签名 APK + 构建说明 |

**非目标（本期不做）**：在线图源/联网检索、账号系统、云同步、下载/缓存到应用私有目录、追更通知。（架构需为"未来联网检索"预留扩展点，但本期不实现。）

### 1.B 输入、输出与约束

**输入（用户/环境侧）**

- 一个或多个本地库根目录（**按绝对路径访问**，需授予 `MANAGE_EXTERNAL_STORAGE` 全部文件访问权限；见 1.C-D2）。
- 目录结构约定：`库根目录 / 漫画名 / 图片文件`（**严格两级**，无"卷/章节"第三级；见 1.C-D1）。
- 图片文件：扩展名或文件头可识别为受支持格式。
- 用户操作：导入目录、切换排序、打开漫画、切换阅读模式、收藏、随机、管理收藏夹。

**输出（App 产出）**

- 主页漫画总览（封面网格 + 名称）。
- 阅读界面（下拉/翻页两种模式，含页码/进度）。
- 收藏夹视图。
- 持久化数据：已导入目录列表、收藏关系、（可选）阅读进度、排序偏好。
- 最终交付：`ComicNest-release.apk`（正式签名）。

**约束**

- **平台**：Android；`minSdk = 26`（Android 8.0），`compileSdk/targetSdk` 采用所选基线的最新稳定版（见 2.2）。（决策依据 Q9：由开发侧选定）
- **只读语义**：绝不复制、移动、修改用户漫画源文件（封面缓存/缩略图仅写入 App 私有目录）。
- **目录访问（Q2 已定）**：需支持访问**任意绝对路径**，因此申请 `MANAGE_EXTERNAL_STORAGE`（全部文件访问）。该权限较敏感、不适合上架应用商店，但本项目**仅用户自行侧载小规模使用**，符合场景；不再采用 SAF 授权模型。
- **语言**：UI 文案中文。
- **性能**：大目录（成百上千部漫画、单部数百张图）下扫描与滚动需流畅，缩略图/图片需异步加载 + 内存与磁盘缓存，避免 OOM。
- **签名合规**：Release 构建使用正式 keystore 签名，`versionCode/versionName` 规范，避免被判为测试包。
- **许可证合规**：见第 2 节；Mihon 为 Apache-2.0（可闭源分发），LocalViewer 为 GPL-3.0（仅作设计参考，不直接复制其源码进闭源产物）。

### 1.C 需求澄清与已确认决策

> 以下为用户已确认的最终决策，作为开发依据（原提问保留为背景说明）。

**D1. 目录层级（原 Q1）**：采用**严格两级**结构 `库根 / 漫画名 / 图片`，漫画名目录内直接是图片，整部漫画作为**单一阅读序列**（无章节层）。
- 影响：需改造 Mihon 的 `source-local`，将其"漫画/章节/图片"三级模型简化为"库根/漫画名/图片"两级模型。

**D2. 目录访问方式（原 Q2）**：需支持访问**任意绝对路径**（主要供用户本人使用）。
- 实现：申请 `MANAGE_EXTERNAL_STORAGE`（全部文件访问），直接按绝对路径读取目录，不走 SAF 授权。
- 合规：该权限敏感、不适合上架商店；因本项目仅侧载自用，可接受。

**D3. 首图/封面规则（原 Q3）**：取漫画名目录内**按文件名排序最小的图片**作为封面（不特殊处理 `cover.*`）。

**D4. 主页浏览方式（原 Q4）**：网格 **无限滚动**（非分页翻页）。

**D5. 随机阅读（原 Q5）**：随机范围为**全部已导入漫画**；随机后进入阅读（起点遵循 D6 进度规则：命中最近 5 本则续读，否则从第一页开始）。

**D6. 阅读进度记忆（原 Q6，关键）**：采用 **LRU 容量 = 5** 的进度记录策略——
- 仅记录**最近阅读的 5 本**漫画的进度；
- 当阅读到"往前第 6 本"（即被挤出最近 5 本之外的漫画）时，**从第一页开始**（不保留其历史进度）；
- 即：任意时刻最多持久化 5 条进度记录，超出则淘汰最久未读的那条。

**D7. 收藏夹语义（原 Q7）**：
- 一部漫画**可属于多个**收藏夹（多对多，指向式引用，不复制文件）；
- 支持收藏夹的**增 / 删 / 改（重命名）**，以及**从收藏夹移除漫画**；
- 当收藏指向的源目录被移动/删除：采用**失效提示 + 自动清理**（标记失效并自动移除失效指向）。

**D8. 图片格式（原 Q8）**：
- **gif：需播放动画**（使用支持动图的解码器，如 Coil + ImageDecoder / 动图 drawable）；
- **bmp：需要支持**；
- **不支持压缩包（cbz/zip/rar），不支持 pdf/epub**——本期仅处理图片目录；
- 支持格式集合：jpg、jpeg、png、webp、gif、bmp（+ 尽量兼容 avif/heif 等系统可解码格式）。
- 影响：可移除 Mihon 中 `Format.Archive` / `Format.Epub` 及 `core:archive` 相关依赖。

**D9. 目标 Android 版本（原 Q9）**：由开发侧选定——`minSdk = 26`（Android 8.0），`compileSdk/targetSdk` 采用所选基线最新稳定版。

**D10. 重名漫画（原 Q10）**：
- **内部唯一键 = 库根路径 + 漫画名**（对用户隐藏）；
- 外部展示名仅为"漫画名"，**允许重名**（不同库根下同名漫画视为不同条目，其图片必然不同，正常并列展示即可）。

**D11. 异常与边界处理（原 Q11）**：全部采用默认策略——
- 空目录 / 无有效图片：跳过不展示（或占位标记"无内容"），不崩溃；
- 图片损坏无法解码：阅读时显示占位错误图并跳过，不崩溃；
- 文件名非数字序号：按自然序 / 字典序稳定排序；
- 已导入目录被用户删除：主页提示失效并允许移除。

**D12. 语言范围（原 Q12）**：**仅中文**（不保留多语言切换 UI；字符串集中于资源文件即可）。

**D13. 交付与签名（原 Q13）**：
- 由**开发侧生成一个新的正式签名密钥**（Release keystore），构建正式签名 APK；
- keystore 及其口令/别名信息**交付给用户保管**，放置于项目目录下（如 `keystore/`，并在 `.gitignore` 中排除以防泄露）；
- APK **仅用户本人小规模侧载使用**，不上架应用商店。

**D14. 品牌与图标（原 Q14）**：App 名称固定 **ComicNest**，需要自定义图标。
- ✅ **图标已实际提供**：`docs/assets/icon/ic/ComicNest.jpg`（**512 × 512 JPG**，蓝底书本图形）。
  - 可用性确认：512×512 足以生成全部启动器密度（最高 xxxhdpi=192）；JPG 无透明通道但原图为满幅圆角方形，可接受。
  - 处理方案（详见 DESIGN §6.4）：legacy 图标直接缩放生成 `mipmap-mdpi~xxxhdpi`；自适应图标以原图内缩作前景、采样浅蓝纯色（约 `#5EB2F6`）作背景，规避 JPG 无透明的白角问题。
- 配色：采用 Material 3；是否启用动态取色（Material You）由开发侧按美观度决定。

### 1.D 运行方式、测试方式与验收标准

**运行方式（开发/构建）**

- 环境：Android Studio（需匹配所选基线的 AGP/Kotlin 版本，见第 2 节）、JDK（Mihon 基线需较新 JDK，建议 21+）、Android SDK。
- 构建：`./gradlew :app:assembleRelease`（正式签名）与 `:app:assembleDebug`（调试）。
- 安装：`adb install -r app-release.apk` 或将 APK 传输到手机侧载安装。
- 首次运行：授予"全部文件访问"权限（`MANAGE_EXTERNAL_STORAGE`）→ 添加/输入一个或多个库根目录的**绝对路径** → 触发扫描 → 主页展示漫画总览。

**测试方式**

- **单元测试**：文件名自然序排序、格式识别、封面选取、收藏夹数据模型、边界（空目录/损坏图片/重名）。
- **仪器/UI 测试**：导入目录流程、主页排序切换、打开漫画、下拉↔翻页模式切换、随机阅读、收藏与收藏夹管理。
- **兼容性测试**：不同分辨率/Android 版本；大目录（≥500 部、单部 ≥300 图）滚动与内存表现；六种图片格式实机验证。
- **性能测试**：冷启动时间、目录扫描耗时、滚动帧率、缩略图加载延迟、内存峰值（无 OOM）。
- **签名验证**：`apksigner verify --print-certs` 确认为正式签名；实机安装不触发"测试版拒装"。

**验收标准（Acceptance Criteria）**

- [ ] AC1：可添加 ≥1 个本地库根目录（**绝对路径**），"全部文件访问"权限与库根路径列表在重启后仍有效（持久化）。
- [ ] AC2：主页正确列出各"漫画名 + 首图预览"（封面=按名排序最小图），无源文件被复制/修改。
- [ ] AC3：主页支持"按名称（默认）/按导入时间"排序切换，网格**无限滚动**流畅。
- [ ] AC4：打开漫画后图片严格按文件名自然序展示（`001` 在 `002` 前）。
- [ ] AC5：默认下拉式阅读，可切换左右翻页，两种模式均可正常翻页与显示进度。
- [ ] AC6：jpg/jpeg/webp/png/gif/bmp 六种格式均可正常显示，其中 **gif 可播放动画**。
- [ ] AC7：随机阅读可从主页一键在**全部已导入漫画**中随机进入一部阅读。
- [ ] AC8：可创建/重命名/删除多个收藏夹，将漫画加入/移出；一部漫画**可属于多个收藏夹**；收藏为指向式（不复制文件）；源目录失效时**提示并自动清理**失效指向。
- [ ] AC9：UI 文案为中文，界面美观（Material 3）。
- [ ] AC10：边界场景（空目录、损坏图片、重名、目录失效）不崩溃，有合理提示/降级。
- [ ] AC11：大目录场景滚动流畅、无 OOM。
- [ ] AC12：交付正式签名 `ComicNest-release.apk`，实机可正常安装并运行；附构建/签名说明与 keystore 交付。
- [ ] AC13：架构分层清晰，"未来联网检索"扩展点已预留（Source 抽象/模块边界）。
- [ ] AC14：**阅读进度仅保留最近 5 本（LRU=5）**；第 6 本（被挤出者）再次打开时从第一页开始。
- [ ] AC15：不同库根下的**同名漫画**以"库根路径+漫画名"为内部唯一键并存，展示仅显示漫画名且互不干扰。

## 2. 技术选型结论

### 2.1 三份参考代码评估

| 项目 | 实际内容 | 技术栈 | 许可证 | 构建复杂度 | 结论 |
|------|----------|--------|--------|-----------|------|
| **mihon-main** | 完整成熟 App 源码 | Kotlin + Jetpack Compose；分层 `domain/data/presentation`；Metro(DI)、Coil3、Room、UniFile(SAF)；AGP 9.4.1 / Kotlin 2.4.20 / compileSdk 37 | **Apache-2.0** | 中（纯 Gradle，无原生/Rust） | ✅ **推荐为主基线** |
| **LocalViewer-main** | 完整 App 源码（EhViewer 系） | Kotlin **Multiplatform** + Compose Multiplatform；**Rust 工具链 + NDK 29**；大量原生编解码（libjxl/libavif/libwebp/libarchive）；minSdk 31 | **GPL-3.0** | **高**（需 Rust + NDK 交叉编译） | ⚠️ **仅作 UI/阅读器体验设计参考**，不复制其源码进闭源产物 |
| **manga-zen-reader-main** | **仅落地页**（`index.html` + `README.md` + svg），README 为宣传性描述，**无任何源码** | 声称 Compose（无实现） | 声称 MIT | — | ❌ **不可用作代码基础**（无代码可复用） |

> 重要提示：`manga-zen-reader-main` 仓库内没有可编译源码，仅有一个营销式 README 和网页，无法作为开发基础。请勿依赖它。

### 2.2 选型决策

**主基线：以 Mihon 为架构与代码基础进行裁剪 + 改造**，理由：

1. **许可证友好**：Apache-2.0，允许闭源修改并分发 APK，契合"交付 APK"目标；LocalViewer 的 GPL-3.0 会强制开源，风险高。
2. **能力天然吻合**：Mihon 已内置本项目所需的几乎全部核心机制（见 2.3 复用清单）。
3. **构建门槛低**：纯 Android（非 Multiplatform）、无 Rust/NDK 交叉编译，比 LocalViewer 更易产出 APK。
4. **架构可扩展**：`source-api`/`source-local` 抽象天然为"未来联网检索"预留扩展点（契合需求 21）。
5. **工程成熟**：清晰分层、DI、缓存、异步、健壮性处理均已具备，减少从零造轮子。

**LocalViewer 的用法**：作为 **UI/UX 与阅读体验的设计参考**（Material 3 动态取色、Webtoon 自动旋转、双页、预加载策略等），**借鉴思路而非复制源码**，以规避 GPL 传染。

**风险提示**：Mihon 工具链非常新（AGP 9.4.1 / Kotlin 2.4.20 / compileSdk 37 / Compose BOM 2026.09），需要**最新版 Android Studio 与 JDK**；若本机环境较旧，可能需降级基线或升级工具链（进入开发前确认）。

| 库/漫画数据 | `domain/.../library/*`、`domain/.../manga/*` | 复用领域模型与仓库接口 | 精简在线源字段；唯一键=库根路径+漫画名（D10） |
| 文件访问 | `com.hippo.unifile.UniFile`（贯穿全项目） | 以 `UniFile.fromFile(File)` 包装绝对路径复用 | **改为 `MANAGE_EXTERNAL_STORAGE` + 绝对路径**，非 SAF 持久化授权（D2） |
| 主题/UI 基础 | `presentation-core`、Material 3 / materialKolor、Coil3 | 复用为 UI 基座 | **仅中文化文案**、品牌化图标（D12/D14） |

**需裁剪/移除的 Mihon 部分**（本期非目标）：在线图源与扩展系统、追踪服务（AniList/MAL 等）、下载管理、备份云同步、telemetry/firebase、widgets 等非必要模块——以降低体积与复杂度（保留 `source-api` 抽象以备未来）。

## 3. 建议的高层架构（基于 Mihon 裁剪）

```
:app                     —— UI(Compose) + 阅读器(Webtoon/Pager) + 主页/收藏/设置
:domain                  —— 领域模型与用例：library / manga / category(收藏夹) / storage
:data                    —— 仓库实现：本地扫描仓库、收藏仓库、进度仓库、设置仓库
:source-local            —— 本地目录 Source（库根/漫画名/图片 扫描 + 封面）
:source-api              —— Source 抽象接口（为"未来联网检索"预留扩展点，本期仅本地实现）
:core:common             —— 工具：ImageUtil(格式识别)、自然序排序、UniFile 封装、协程上下文
:core:ui / presentation-core —— Material 3 主题、通用组件、中文字符串资源
```

数据流：SAF 授权目录 → `source-local` 扫描 → 领域模型（漫画/封面/收藏）→ Compose 主页/阅读器渲染；缩略图与图片经 Coil3 异步加载 + 内存/磁盘缓存。
